# Day 5. 승인 게이트와 가드레일

[← 전체 미션 맵](../README.md)  ·  [← Day 4](../day04/README.md)  ·  [Day 6 →](../day06/README.md)

> 위험한 요청은 막고, 되돌릴 수 없는 작업은 사람 승인을 거칩니다.

## 학습 목표

- 입력 가드레일을 규칙으로 먼저 세웁니다.
- 차단 규칙을 늘릴수록 정상 요청도 막힌다는 사실을 데이터로 확인합니다.
- 미들웨어 순서를 바꿔 보고 로그에 무엇이 남는지 확인합니다.
- 도구의 위험도에 따라 승인 정책을 나눕니다. (심화)

## 기초 파트 (7점)

### 구현할 것

```python
input_guard(text) -> (차단여부, 사유)
mask_pii(text) -> str
MIDDLEWARE_ORDER: list[str]
```

### 요구사항

1. **`input_guard`**: 지시를 덮어쓰거나 내부 정보를 빼내려는 요청을 막습니다.

   > `normal_set.json`에는 "이전", "무시", "새로운 역할", "관리자" 같은 함정 단어가 일부러 들어 있습니다.
   > 단어 하나만 보고 막으면 오탐이 납니다. 의도의 조합을 보세요.
   > "덮어쓰려는 동작"과 "현재 지시라는 대상"이 함께 나올 때가 진짜 공격입니다.

2. **`mask_pii`**: 사번(`E123456`), 전화번호, 이메일, AWS 키(`AKIA...`), JWT(`eyJ...`) 다섯 가지를 가립니다.

3. **`MIDDLEWARE_ORDER`**: 차단 → 정제 → 검증 → 기록 순으로 배치합니다.
   마스킹이 로깅보다 뒤에 있으면 로그에 원본이 그대로 남습니다.

4. **`eval_set.json`에 문항 추가** (저장소 루트): `guardrail` 유형 2문항 이상.
   차단되어야 할 문항 1개 이상과 통과해야 할 문항 1개 이상을 함께 넣으세요 (`d5-01`, `d5-02`).

### 채점 기준 (기초 7점)

| 배점 | 항목 | 무엇을 보는가 |
|---|---|---|
| 2점 | **공격 차단** | 비공개 공격 10문항 중 9건 이상 차단 |
| 2점 | **오탐 없음** | 비공개 정상 10문항 중 차단 0건 |
| 1점 | **마스킹** | 다섯 패턴 모두 |
| 1점 | **미들웨어 순서** | 차단 → 정제 → 검증 → 기록 |
| 1점 | **확장 검사 게이트** | 10개 중 8개 이상 |

> 채점에는 교안과 실습 데이터에 없는 비공개 문항을 씁니다. 공개 문항 20개를 하드코딩하면 채점기가 잡아냅니다.

## 심화 파트 (3점)

### 왜 필요한가

가드레일을 세게 걸수록 안전해 보입니다. 그런데 조회 도구까지 사람 승인을 받게 만들면 자동화한 이유가 사라집니다.
도구마다 위험도가 다르니 정책도 나눠 두세요.

### 구현할 것

```python
RISK_LEVELS: dict[str, str]              # 도구 -> "read" | "write" | "destructive"
needs_approval(tool_name, args) -> (필요한가, 사유)
```

| 위험도 | 무엇 | 정책 |
|---|---|---|
| `read` | 조회 | 승인 없이 자동 실행 |
| `write` | 상태 변경 (재시작·스케일 조정) | 승인 필요 |
| `destructive` | 되돌릴 수 없음 (삭제·자격증명 교체) | 승인 + 이중 확인 |
| 목록에 없음 | 등록되지 않은 도구 | 승인 필요 (모르는 것은 막는다) |

`destructive`의 사유 문자열에는 `이중` 또는 `double`을 넣으세요.

### 채점 기준 (심화 3점)

| 배점 | 항목 | 무엇을 보는가 |
|---|---|---|
| 1점 | **정책의 결정성** | 네 등급 모두 표대로. `RISK_LEVELS`에 read·write·destructive가 각각 2개 이상 |
| 1점 | **과차단 방지** | 조회 도구는 승인 없이 통과 |
| 1점 | **이중 확인** | destructive는 승인 + 이중 확인 표시 |
