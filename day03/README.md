# Day 3. 장애 원인 조사 Agent

[← 전체 미션 맵](../README.md)  ·  [← Day 2](../day02/README.md)  ·  [Day 4 →](../day04/README.md)

> 도구 세 개로 장애 원인을 좁혀 갑니다. 다음에 어떤 도구를 부를지는 모델이 정합니다.

## 학습 목표

- LangGraph의 State, Node, 조건부 엣지, 순환을 조립해 봅니다.
- ReAct 루프가 무엇을 반복하는지 이해합니다. 생각 → 도구 호출 → 결과 관찰 → 다시 판단.
- 복합 질문에서는 도구 2개가 순서대로 움직입니다. 앞 도구가 내놓은 값이 뒤 도구의 인자로 들어가는지 확인합니다.
- 순환에는 반드시 탈출 조건이 필요하다는 것을 직접 겪어 봅니다. (심화)

## 시나리오

`payment-api`에서 5xx가 급증합니다. 당직자는 이렇게 움직입니다.

1. 최근 배포가 있었나? → 있다면 그 시각이 언제인가
2. 그 시각 전후 로그에 무엇이 찍혔나? ← 앞 단계의 결과가 있어야 볼 구간이 정해진다
3. 지표는 어떻게 움직였나?

2번은 1번의 결과가 나와야 시작할 수 있습니다. 이런 순서 의존을 연쇄라고 부릅니다.

### 구현할 것

```python
TOOLS                    # @tool 3개 이상 (조회형 · 계산형 · 판단형)
build_agent(llm=None)    # 컴파일된 LangGraph 그래프
```

### 요구사항

1. 도구 3개: `get_deploy_history`, `get_logs`, `get_metrics`
   - 각 docstring은 30자 이상이고 "언제 쓰는지"가 적혀 있어야 합니다.
   - `args_schema`를 Pydantic으로 지정하세요.
   - 반환은 문자열입니다. 모델이 읽을 것이므로 사람이 읽을 수 있게 씁니다.
   - **같은 인자에는 항상 같은 결과가 나와야 합니다.** `practice/data/`의 고정 데이터를 쓰세요.

2. 그래프: `agent` 노드와 `tools` 노드 사이에 순환이 있어야 합니다.
   `create_react_agent`를 써도 되고 `StateGraph`로 직접 만들어도 됩니다.

3. 연쇄: 배포 이력을 먼저 조회하고, 그 시각을 로그 조회의 인자로 넘겨야 원인에 도달합니다.

4. `eval_set.json` (저장소 루트)에 문항을 추가합니다. `no_tool`, `single_tool`, `multi_tool` 세 유형을 각각 1개 이상 쓰고, id는 `d3-01` 형식으로 이어 붙입니다.

## 심화 파트 (3점)

### 왜 필요한가

순환 그래프는 멈추지 않을 수 있습니다. 모델이 같은 도구를 계속 부르면 토큰과 시간이 무한정 나갑니다.
호출 예산과 종료 조건을 함께 달아 두세요.

### 구현할 것

```python
MAX_TOOL_CALLS                              # 한 번의 조사에서 허용할 도구 호출 상한
should_stop(messages, tool_calls_made)      # (중단할까, 이유) 를 반환
```

이 판정을 `build_agent`가 실제로 쓰도록 연결하세요.

### 요구사항

1. 결정적 판정: `should_stop`은 LLM을 호출하지 않습니다.

   | 조건 | 반환 |
   |---|---|
   | `tool_calls_made >= MAX_TOOL_CALLS` | `(True, "예산 초과")` |
   | 같은 도구를 같은 인자로 2회 이상 호출함 | `(True, "중복 호출")` |
   | 세 도구를 모두 한 번 이상 호출함 | `(True, "근거 충분")` |
   | 그 외 | `(False, ...)` |

   `MAX_TOOL_CALLS`는 3 이상 8 이하로 정합니다.

2. 연결: 모델이 도구를 계속 부르려 해도 그래프가 `MAX_TOOL_CALLS`를 넘지 않아야 합니다.

### 채점 기준 (심화 3점)

| 배점 | 항목 | 무엇을 보는가 |
|---|---|---|
| 1점 | **판정의 결정성** | 네 조건에서 각각 표대로 동작. 상수 반환이면 실패 |
| 1점 | **예산 준수** | 모델이 무한히 도구를 부르는 대본에서 호출 수가 상한 이하로 멈춤 |
| 1점 | **조기 종료** | 근거가 충분하면 상한에 닿기 전에 멈춤 |
